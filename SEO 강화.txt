사장만(sajangman) 전체 사이트의 네이버/구글 자연검색 SEO를 대폭 강화해줘.

중요:
이번 작업은 단순히 metadata에 키워드를 많이 넣는 작업이 아니다.

실제 네이버 서치어드바이저 검색 데이터를 확인한 결과
사장만은 이미 다음 검색어에서 노출/클릭이 발생하고 있다.

실제 검색 데이터:

- 원가율 계산: 835 노출 / 31 클릭 / CTR 3.7%
- 객단가 계산: 275 노출 / 24 클릭 / CTR 8.7%

- 원가계산기: 501 노출 / 13 클릭 / CTR 2.6%
- 원가율계산기: 22 노출 / 10 클릭 / CTR 45.5%

- 배민 수수료 퍼센트: 162 노출 / 7 클릭
- 배달 수수료 계산: 62 노출 / 7 클릭
- 배달앱 민족 사장님 수수료
- 배달의민족 수수료 계산
- 땡겨요 수수료 계산
- 쿠팡 수수료 계산 방법

- 종합소득세 계산기: 1,531 노출 / 4 클릭 / CTR 0.3%

즉 현재 검색엔진이 이미 사장만을

"자영업자 계산기 / 원가 / 마진 / 수수료 / 세금 / 사업 실무"

사이트로 인식하기 시작한 상태다.

이 방향을 중심으로 SEO를 확장한다.


==================================================
1. 가장 중요한 원칙
==================================================

키워드 스터핑 금지.

페이지마다 하나의 명확한 검색 의도를 설정한다.

각 계산기 페이지를 단순 계산 UI가 아니라:

"계산 도구 + 계산 방법 + 공식 + 예시 + FAQ + 관련 도구"

가 있는 독립적인 검색 랜딩페이지로 강화한다.

기존 계산 기능은 절대 변경하지 않는다.

SEO를 위해 사용자 경험을 해치는
긴 의미 없는 텍스트를 상단에 추가하지 않는다.

==================================================
3. TITLE 최적화
==================================================

각 페이지 title을 실제 검색어 중심으로 점검한다.

예:

원가율 페이지:

원가율 계산기 | 원가율 계산 방법·공식 - 사장만

객단가:

객단가 계산기 | 평균 객단가 계산 방법 - 사장만

배달 마진:

배달 마진 계산기 | 배달앱 수수료·순이익 계산 - 사장만

부가세:

부가세 계산기 | 공급가액·부가가치세 계산 - 사장만

사업소득세:

사업소득세 계산기 | 사업소득 원천징수 계산 - 사장만

종합소득세:

종합소득세 계산기 | 개인사업자 예상 세금 계산 - 사장만

손익분기점:

손익분기점 계산기 | BEP 계산 방법·공식 - 사장만


IMPORTANT:

title마다 실제 페이지 기능과 일치해야 한다.

실제 제공하지 않는 계산/정보를 title에 넣지 않는다.

title은 자연스러운 한국어로 작성한다.

키워드 반복 금지.


==================================================
4. META DESCRIPTION
==================================================

모든 calculator/resource/document 페이지의
description을 개별 작성한다.

페이지마다 동일 description 복붙 금지.

예:

원가율:

"판매가와 원가를 입력하면 원가율을 바로 계산할 수 있습니다. 원가율 계산 공식과 음식점·카페 등 자영업자가 알아두면 좋은 원가 관리 방법도 함께 확인하세요."

객단가:

"매출액과 고객 수를 입력해 평균 객단가를 계산하세요. 객단가 계산 공식과 매출 분석에 활용하는 방법을 쉽게 확인할 수 있습니다."

description은 검색 결과에서 클릭하고 싶게 만들되
과장 광고 문구를 사용하지 않는다.


==================================================
5. 계산기 페이지 콘텐츠 구조
==================================================

주요 계산기 페이지를 다음 구조로 통일한다.


H1:

"원가율 계산기"

짧은 설명

↓

CALCULATOR

실제 계산기

↓

H2:

"원가율 계산 방법"

공식:

원가율(%) = 원가 ÷ 판매가 × 100

↓

H2:

"원가율 계산 예시"

실제 숫자 예제

↓

H2:

"원가율은 어떻게 활용하나요?"

실무 설명

↓

H2:

"자주 묻는 질문"

FAQ 3~5개

↓

H2:

"함께 사용하면 좋은 계산기"

관련 계산기 internal link


IMPORTANT:

페이지 상단은 계산기가 우선이다.

SEO 때문에 사용자가 계산기를 찾기 위해
긴 글을 스크롤해야 하는 구조로 만들지 않는다.


==================================================
6. 종합소득세 / 사업소득세 CTR 개선
==================================================

이 부분은 매우 중요.

현재:

종합소득세 계산기:
1,531 노출 / 4 클릭 / CTR 0.3%

사업소득세 계산기:
830 노출 / 5 클릭 / CTR 0.6%

노출량에 비해 클릭률이 낮다.

해당 페이지의:

title
description
H1
검색 의도 일치 여부
계산기가 실제 검색 의도를 만족하는지

집중 점검한다.


title이 모호하거나 브랜드명이 먼저 나오면 수정한다.

검색 핵심어를 title 앞쪽에 배치한다.

예:

종합소득세 계산기 | 개인사업자 예상 세금 계산 - 사장만

사업소득세 계산기 | 3.3% 사업소득세 계산 - 사장만

단 실제 계산 로직과 맞는 경우에만 사용.

7. 원가율 SEO 집중 강화
==================================================

원가율은 현재 실제 클릭이 가장 강하게 발생하고 있으므로
핵심 SEO hub로 강화한다.

원가율 페이지에서 자연스럽게 연결:

원가 계산
마진율 계산
순이익 계산
손익분기점 계산
배달 마진 계산

그리고 관련 자료가 있다면:

원가율 계산 방법
음식점 원가 관리
카페 원가율
마진율과 원가율 차이

등으로 internal link.


관련 계산기 영역:

"같이 사용하면 좋은 계산기"

를 페이지 하단에 추가한다.


==================================================
8. 검색어 변형 자연스럽게 수용
==================================================

실제 검색에서:

원가율 계산
원가율계산
원가율 계산기
원가율계산기

처럼 띄어쓰기 변형이 발생한다.

이를 위해 같은 단어를 억지로 반복하지 않는다.

본문을 자연스럽게 작성하면 검색엔진이 변형을 이해할 수 있도록 한다.

예:

"원가율 계산기는 판매가와 원가를 이용해 원가율을 계산하는 도구입니다."

정도로 충분하다.


==================================================
9. INTERNAL LINK 강화
==================================================

현재 사이트의 가장 중요한 개선 중 하나.

모든 계산기 페이지 하단에:

"함께 사용하면 좋은 계산기"

3~5개 표시.


예:

원가율 계산기
→ 마진율 계산기
→ 손익분기점 계산기
→ 순이익 계산기
→ 배달 마진 계산기


배달 마진 계산기
→ 배달 수수료
→ 원가율
→ 순이익
→ 손익분기점


종합소득세
→ 사업소득세
→ 부가세
→ 간이과세자 관련 자료


단순히:

"자세히 보기"

만 anchor text로 사용하지 말고

"원가율 계산기"
"손익분기점 계산기"

처럼 목적이 명확한 anchor text를 사용한다.

==================================================
14. STRUCTURED DATA
==================================================

현재 schema 구조를 먼저 분석한다.

중복 schema를 만들지 않는다.


적절한 페이지:

WebSite
Organization 또는 운영주체 정보
BreadcrumbList
WebApplication/SoftwareApplication 등

현재 콘텐츠에 실제 FAQ가 있고
검색엔진 정책상 적절한 경우 FAQ 구조를 semantic하게 구성.

IMPORTANT:

검색 노출만을 목적으로
가짜 review
rating
aggregateRating

절대 생성하지 않는다.

16. CANONICAL
==================================================

모든 indexable 상세 페이지의 canonical 확인.

18. NAVER SEO
==================================================

네이버 검색 유입이 실제 발생하고 있으므로
네이버 기준도 함께 점검한다.

확인:

robots.txt
sitemap.xml
canonical
title
description
H1
내부링크
SSR/HTML에서 핵심 콘텐츠 확인 가능 여부

중요 SEO 콘텐츠를
클라이언트 JS 실행 후에만 생성하지 않는다.

가능하면 서버 렌더링된 HTML에:

H1
설명
공식
본문
관련 링크

가 포함되게 한다.

==================================================
20. PERFORMANCE
==================================================

SEO 리뉴얼 때문에
성능이 떨어지지 않게 한다.

확인:

next/image
font
LCP
CLS
불필요한 client component
bundle size

SEO 콘텐츠만 있는 section을
불필요하게 "use client"로 만들지 않는다.


==================================================
21. 현재 잘 되는 URL 보호
==================================================

매우 중요.

이미 검색 노출/클릭이 발생하는 페이지의
URL slug를 절대 변경하지 않는다.

특히:

원가율
객단가
사업소득세
종합소득세
배달 수수료/마진

관련 기존 URL 유지.

URL을 변경해야 할 특별한 이유가 있다면
작업하지 말고 먼저 보고한다.

이미 색인된 URL을
새 URL로 무작정 교체하면 안 된다.

==================================================
최종 목표
==================================================

사장만을 단순히

"계산기 몇 개 있는 사이트"

가 아니라 검색엔진이

"자영업자·소상공인을 위한
계산기 + 문서작성 + 사업 운영 정보 서비스"

로 명확하게 이해하도록 만든다.

특히 이미 성과가 발생하고 있는:

원가율
객단가
마진
배달 수수료
사업소득세
종합소득세

검색 클러스터를 가장 먼저 강화한다.

기존 검색 성과를 잃지 않는 것을
신규 키워드 확보보다 우선한다.
